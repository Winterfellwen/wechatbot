# AI运势功能设计规范

## 概述

为微信小程序添加AI运势功能，支持中西方两种预测体系，结合真实易经、八字、紫微等中国传统文化，以及星座、塔罗、占星等西方文化典故。

## 功能范围

### 支持的预测类型

**中国预测：**
- 易经卦象 - 基于易经六十四卦的占卜分析
- 八字命理 - 基于出生年月日时的八字分析
- 紫微斗数 - 中国传统紫微斗数命盘分析

**西方预测：**
- 星座分析 - 十二星座的性格分析、运势预测
- 塔罗占卜 - 塔罗牌阵解读
- 占星术 - 行星位置、相位分析

### 用户输入要求

- 不强制收集微信头像、昵称
- 其他信息（出生日期、时辰、性别等）让用户自由选择提供
- 不同预测类型需要不同的输入信息

## 架构设计

### 整体架构

采用模块化子包架构，创建新的`fortune`子包，包含以下模块：

```
fortune/
├── pages/           # 页面组件
├── components/      # 可复用组件
├── services/        # 业务逻辑服务
├── data/            # 本地md文档数据
└── utils/           # 工具函数
```

### 三层架构

1. **用户界面层** - 页面展示、交互逻辑
2. **业务逻辑层** - 预测算法、数据处理
3. **数据服务层** - 本地存储、AI API

### 核心模块

- **中国预测模块** - 易经、八字、紫微
- **西方预测模块** - 星座、塔罗、占星
- **AI服务层** - 统一的AI API调用接口

## 页面结构设计

### 页面层级

1. **首页** (`fortune/pages/index`) - 展示所有预测类型入口
2. **预测类型选择** (`fortune/pages/types`) - 选择具体的预测类型
3. **信息输入** (`fortune/pages/input`) - 输入个人信息
4. **结果展示** (`fortune/pages/result`) - 展示预测结果
5. **历史记录** (`fortune/pages/history`) - 保存之前的预测结果
6. **每日运势** (`fortune/pages/daily`) - 自动推送每日运势

### 首页布局

选择方案A（分类展示）：
- 中国运势区域：易经、八字、紫微
- 西方运势区域：星座、塔罗、占星
- 每日运势入口

### 导航结构

- 主导航：底部TabBar（首页、历史、我的）
- 子页面：预测类型选择 → 信息输入 → 结果展示
- 特殊页面：每日运势（可设置提醒）

## AI服务设计

### AI服务架构

三层架构：
1. **前端界面** - 用户交互、数据收集
2. **AI服务层** - 提示词生成、API调用
3. **AI API** - OpenAI/Claude等

### API调用流程

1. 收集用户输入
2. 生成提示词
3. 调用AI API
4. 解析响应
5. 格式化结果

### 提示词工程设计

**中国预测提示词示例（易经）：**
```
你是精通易经的AI分析师。根据用户信息和问题，生成一个易经卦象。要求：
1. 生成随机卦象（1-64）
2. 解读卦辞和爻辞
3. 结合用户问题给出建议
4. 引用相关典故
```

**西方预测提示词示例（星座）：**
```
你是精通星座学的AI分析师。根据用户星座和问题，进行星座运势分析。要求：
1. 分析星座特质
2. 预测今日运势
3. 结合希腊神话典故
4. 给出具体建议
```

### API配置

- **主要API：** OpenAI GPT-4
- **备选API：** Claude 3.5 Sonnet
- **国内API：** 文心一言/通义千问
- **请求参数：**
  - temperature: 0.7-0.9
  - max_tokens: 1000-2000
  - top_p: 0.9

### 响应处理策略

1. **内容解析** - 从AI响应中提取结构化数据
2. **格式转换** - 将AI文本转换为小程序可用的格式
3. **错误处理** - 处理API调用失败、响应异常等情况
4. **缓存机制** - 相同输入缓存结果，减少API调用

### 费用控制策略

- **每日限额** - 限制每用户每日调用次数
- **缓存策略** - 相同结果缓存24小时
- **降级方案** - API失败时使用本地模板

## 错误处理设计

### 错误分类

1. **网络错误** - 连接超时、网络断开
2. **API错误** - 限流、认证失败、服务不可用
3. **数据错误** - 输入无效、解析失败

### 错误处理策略

**网络错误：**
- 自动重试3次，间隔递增
- 用户提示："网络连接不稳定，请检查网络后重试"
- 降级方案：使用本地缓存的运势模板

**API错误：**
- 限流处理：等待后重试，或切换备用API
- 认证失败：提示用户重新登录或检查配置
- 服务不可用：切换到备用AI服务

**数据错误：**
- 输入验证：实时验证用户输入格式
- 错误提示：明确指出输入错误并提供修正建议
- 解析失败：使用默认模板生成基础运势

### 降级方案设计

1. **一级降级** - 切换备用AI API（OpenAI → Claude → 国内API）
2. **二级降级** - 使用本地缓存的运势模板
3. **三级降级** - 生成基础运势框架，提示用户稍后完善
4. **最终保障** - 显示"服务暂时不可用"，记录错误日志
