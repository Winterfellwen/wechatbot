# AI 点菜功能设计文档

**创建日期**: 2026-05-20
**功能名称**: AI 点菜
**子包目录**: `ai-order/`

---

## 1. 功能概述

AI 点菜是一个微信小程序子包，提供商家菜单管理和客户智能推荐下单功能。商家通过 AI 对话管理菜单（上传/添加/删除/更新菜品），客户通过 AI 对话获取菜品推荐并完成虚拟下单。

---

## 2. 核心特性

| 特性 | 说明 |
|------|------|
| 双入口 | 入口页选择：商家入口 / 客户入口 |
| 商家对话 | 通过对话添加/删除/更新菜品，AI 引导提供必要信息 |
| 文件上传 | 支持 Excel/DOCX 批量导入菜单 |
| 客户推荐 | 根据客户口味偏好推荐菜品 |
| 虚拟下单 | 确认选择后生成虚拟订单 |
| 语音输入 | 两端均支持语音输入 |
| 商户切换 | 客户可切换不同商家 |

## 3. 数据结构

### 3.1 菜品

```json
{
  "id": "uuid-string",
  "name": "菜品名称",
  "price": 28.00,
  "image": "base64或URL",
  "description": "菜品描述",
  "taste": "口味（如：麻辣、咸甜、酸甜）",
  "spicyLevel": 0-5,

```

### 3.2 商家菜单

```json
{
  "id": "merchant-id",
  "name": "商家名称",
  "dishes": [菜品数组]
}
```

### 3.3 虚拟订单

```json
{
  "orderId": "order-uuid",
  "merchantId": "商家ID",
  "dishes": [已选菜品],
  "totalPrice": 0,
  "status": "confirmed"  // 虚拟订单状态
}
```

## 5. 页面详情

### 5.1 入口页 (index)

- 两个大按钮：商家入口、客户入口
- 客户入口显示当前商家名称，可切换

### 5.2 商家对话页 (merchant)

**功能**:
- 文字输入 + 语音输入
- 文件上传（Excel/DOCX 菜单文件）
- 图片上传（菜品图片）
- AI 对话式菜单管理

**对话流程示例**:
```
用户: 添加菜品
AI: 请提供菜品名称和价格，如：宫保鸡丁 28元
用户: 宫保鸡丁 28元
AI: 请提供图片（可上传或描述），口味（可选），辣度（0-5）
...
AI: 已添加【宫保鸡丁】28元，确认吗？回复"确认"或"取消"
用户: 确认
AI: 已保存！当前菜单共 X 个菜品
```

**AI 引导的信息收集**:
- 必需：菜品名、价格
- 可选：图片、描述、口味、辣度
- 状态：添加时默认为 online

**菜品操作**:
- 添加：AI 收集信息后确认保存
- 删除：AI 确认后删除
- 更新状态：AI 接受指令（如"把宫保鸡丁下架"）

### 5.3 客户对话页 (customer) — "分屏探索"布局

**核心理念**：抛弃传统全屏聊天界面，采用"上菜下聊"分屏布局。菜品信息始终可见，AI 作为智能导购辅助决策。

**布局结构**（竖屏，从上到下）：

```
┌─────────────────────────────┐
│    菜品网格区（约 60%）        │
│  ┌─麻辣区──────────────────┐ │
│  │ [宫] [麻] [水]           │ │  ← scroll-view 横向
│  │  28元  18元  48元        │ │
│  ├─酸甜区──────────────────┤ │
│  │ [糖] [番]                │ │
│  │  38元  15元              │ │
│  ├─清淡区──────────────────┤ │
│  │ [红]                     │ │
│  │  32元                    │ │
│  └─────────────────────────┘ │
├─────────────────────────────┤
│    快捷提问栏                  │
│  [看看菜单] [辣的] [随便]     │
├─────────────────────────────┤
│    AI 对话区（约 35%）         │  ← 显示 1-2 条最近消息
│  ┌─────────────────────────┐ │
│  │ AI: 推荐宫保鸡丁...      │ │
│  │ 用户: 来一份             │ │
│  └─────────────────────────┘ │
│  [_______________________][➤]│  ← 输入框+发送
├─────────────────────────────┤
│  购物车栏（常驻底部）            │
│  🛒 3件          合计 ¥76 去下单│
└─────────────────────────────┘
```

**菜品网格区设计**：
- 按口味分区：麻辣（红色渐变）、酸甜（橙色渐变）、清淡（绿色渐变）
- 每区有彩色头部标签 + 横向滑动卡片行 (`scroll-view`)
- 每张菜品卡片：首字图（彩色渐变圆底+白色大字，颜色由口味决定）+ 菜名 + 价格 + 辣度图标
- 点击卡片 → 直接加入购物车（有动画反馈）
- AI 推荐时 → 对应卡片外圈发光脉冲动画，自动滚动到可见区

**AI 对话区设计**：
- 紧凑型，默认显示最近 1-2 条对话
- 点击输入框时对话区扩展（滚动到最新），发送/收起后恢复
- 快捷提问 chip（圆角标签）："看看菜单"、"有什么推荐"、"今天吃啥"、"辣的"等
- AI 气泡内推荐菜品自动关联到上区高亮

**购物车与下单流程**：
- 底部购物车栏常驻显示：件数 + 合计金额 + "去下单"按钮
- 点击 "去下单" → 从底部弹出半屏操作面板（非遮罩弹窗），支持上滑展开全屏
- 操作面板内容：已选菜品列表（每项可调数量）、备注输入框、合计金额、确认下单按钮
- 数量增减有动画反馈
- 确认后：保存到 localStorage + 对话区插入一条"下单成功"消息（非弹窗）
- 购物车数据跨页面保留（同一商户会话期间）

**交互联动**：
1. AI 回复提到某道菜 → 上区该卡片脉冲高亮 + 自动滚动到视野
2. 上区卡片点击加购物车 → 下区 AI 显示"已加入：宫保鸡丁"轻提示
3. 用户说"有什么推荐" → AI 回复 + 上区最多 3 张卡片同时高亮
4. 快捷提问 chip 点击 → 自动发送消息并触发 AI 回复

### 5.4 菜品图片策略

无真实菜品图片时，使用**首字图**替代：
- 每个菜品卡片显示其名称首个汉字，白色字体，置于彩色渐变圆底上
- 颜色由口味决定：麻辣→红橙渐变、酸甜→黄橙渐变、清淡→绿青渐变
- 视觉效果类似 Google 联系人首字母头像，在小程序环境下可靠显示
- 首字图卡片同时也是未来真实图片的占位布局，后续只需替换 `image` 字段即可

## 6. API 设计

### 6.1 对话接口

**POST** `/api/ai-order/chat`

请求:
```json
{
  "mode": "merchant" | "customer",
  "merchantId": "商家ID",
  "messages": [
    { "role": "user", "content": "用户消息" },
    { "role": "assistant", "content": "AI 回复" }
  ],
  "menuData": { /* 当前菜单数据，用于 AI 上下文 */ }
}
```

响应:
```json
{
  "reply": "AI 回复内容",
  "actions": [ /* 可选：AI 执行的操作 */ ]
}
```

### 6.2 菜品管理接口

| 接口 | 方法 | 说明 |
|------|------|------|
| `/api/ai-order/menu/add` | POST | 添加菜品 |
| `/api/ai-order/menu/update` | POST | 更新菜品 |
| `/api/ai-order/menu/delete` | POST | 删除菜品 |
| `/api/ai-order/menu/list` | GET | 获取菜单 |

### 6.3 文件解析接口

**POST** `/api/ai-order/parse`

上传 Excel/DOCX 文件，AI 解析返回菜品列表供商家确认。

### 6.4 订单接口

**POST** `/api/ai-order/order`

虚拟下单，仅存储订单记录用于展示。

### 6.5 配置接口

**GET** `/api/ai-order/config`

获取点菜功能专用的 AI 配置（模型、API Key 等）。
